# 授权操作稳定性与交互反馈设计

## 目标

降低批量 2FA/OAuth 授权中的重复操作、无效重试和过快请求，同时让“开始授权”“刷新账号”“人工验证接管”等操作有清晰、可观察的状态反馈。服务商要求人工验证时仍由用户完成，不自动绕过、伪装或削弱验证。

## 方案选择

考虑了三种实现方式：

1. 只在前端给按钮加 loading 和防重复点击。改动小，但 Worker 仍可能因为网络抖动或重复阶段产生不必要请求。
2. 只在 Worker 增加全局限流。能降低请求频率，但页面无法解释当前正在发生什么，用户仍可能重复点击。
3. **前端交互锁定 + Worker 阶段去重与退避 + 状态动画（采用）**。前端负责合并用户意图并反馈状态，Worker 负责在账号和阶段粒度控制请求频率，整体改动集中在现有模块，且可以复用现有任务状态和人工接管协议。

## 行为设计

### 前端操作

- “开始授权”提交期间锁定按钮，显示旋转图标和“启动中”；相同批量提交请求只保留一个进行中的 Promise。
- “刷新账号”提交期间锁定按钮，显示“刷新中”；刷新失败保留上一次成功列表，并显示稳定的错误提示。
- 任务轮询继续使用现有节奏；任务状态未变化时不触发视觉抖动，状态变化时更新状态徽标和进度文本。
- 人工验证截图更新时淡入；点击坐标和输入发送后显示短暂的操作反馈，用户可以继续手动接管。

### Worker 稳定性

- 同一任务、账号和阶段只执行一次有效动作；重复触发直接复用已有结果或忽略。
- 网络失败使用有限次数的指数退避并加入轻微抖动，达到上限后进入现有失败状态，不无限重试。
- 保持现有 TOTP 剩余时间保护和人工验证等待策略，不增加自动点击频率，也不尝试处理 CAPTCHA。
- 日志和 API 响应继续只返回稳定状态与错误类别，不记录密码、TOTP、Cookie 或人工验证截图内容。

## 动画与可访问性

- 复用现有 Vue/CSS/Lucide 体系，不引入新的动画库。
- 按钮 loading 使用短时旋转；状态卡和账号行使用淡入/颜色过渡；成功、失败和需人工验证使用不同的状态色。
- `prefers-reduced-motion: reduce` 下关闭位移动画和循环旋转，仅保留即时颜色与文本变化。
- 动画只表达正在处理、已完成或需要人工操作，不延迟真实请求，也不隐藏错误。

## 验证

- 前端测试覆盖重复点击只创建一个任务、刷新请求合并、处理中状态和 reduced-motion 样式。
- Worker 测试覆盖相同阶段去重、退避上限和原有人工接管路径。
- 运行现有 Worker、Rust 和前端检查；生产发布前确认健康检查、任务取消和人工验证点击仍然可用。
